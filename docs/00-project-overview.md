# 00 — Project Overview

> **Project:** Furnishing MES — Manufacturing Execution System
> **Codename / Odoo module:** `furnishing_mes`
> **Platform:** Odoo 18.0 Community Edition (Dockerised)
> **Status:** Phase 0 — Documentation complete

---

## 1. Problem Statement

The customer is a furnishing manufacturer whose production planning and shop-floor
reporting currently run on manually maintained Excel workbooks (e.g. the
*"DAY WISE OUTPUT"* sheet referenced in the requirements). This creates:

| Pain | Consequence |
|---|---|
| Manual Excel planning | Slow, error-prone, not capacity-aware |
| No centralised production database | No historical trend, no single source of truth |
| Downtime reasons captured on paper | Losses cannot be quantified or analysed |
| No machine utilisation visibility | Bottlenecks and idle machines go unnoticed |
| Backlog tracked ad hoc | Delayed and blocked orders surface too late |
| Maintenance is reactive | Unplanned breakdowns dominate downtime |
| Management has no dashboards | Decisions are made on stale, aggregated numbers |

## 2. Solution Summary

A single custom Odoo 18 Community module, **`furnishing_mes`**, that turns Odoo's
native Manufacturing (`mrp`) and Maintenance (`maintenance`) apps into a complete
Manufacturing Execution System tailored to the customer's process.

Odoo is **both the backend and the frontend**:

- **Business logic & data** — Odoo ORM (Python 3.11+), PostgreSQL 15
- **UI** — Odoo views (List, Form, Kanban, Pivot, Graph, Calendar, Search) plus
  custom **OWL 2** components for the Shop-Floor Terminal, Scheduling Board and
  Executive Dashboard
- **Security** — Odoo `res.groups` ACLs, record rules and the Portal
- **Automation** — `ir.cron`, `base_automation`, `mail` (activities + email)

There is **no separate React app and no separate FastAPI service.** Everything
ships as one installable Odoo addon.

## 3. Scope

### In scope (Phases 1–15)

1. Production planning automation driven by a machine capacity matrix
2. Daily production plan, target capture and actual output tracking
3. Production monitoring (machine-wise, department-wise, real-time)
4. Backlog and carry-forward order management
5. Machine utilisation monitoring and OEE
6. Downtime capture and loss-reason analysis
7. Machine maintenance management (preventive + breakdown)
8. Production resource / manpower management
9. Analytics and management dashboards
10. Alerts and notifications
11. The full automated reporting suite (PDF + XLSX + scheduled MIS)
12. Customer self-service portal

### Explicitly deferred

- **ERP 10.8 integration (Requirement 11).** Not built now. The architecture
  reserves an integration seam for it — see
  [`09-erp-integration-roadmap.md`](09-erp-integration-roadmap.md). Until then all
  upstream master data (Sales Orders, Work Orders, Item Master, BOM, Customer
  Master) is seeded as **mock/demo data inside Odoo**.

### Out of scope

- IoT / PLC / OPC-UA automatic machine signal capture (data entry is manual +
  Excel import)
- Quality control module (`quality_control` is Odoo Enterprise; not requested)
- Payroll, finance/accounting beyond Odoo defaults

## 4. Stakeholders and Personas

| Persona | Odoo user type | Primary surface | Needs |
|---|---|---|---|
| **Operator / Employee** | Internal | Shop-Floor Terminal (tablet) | Start/stop assigned work orders, log output, log downtime |
| **Supervisor** | Internal | Backoffice + approval queues | Shift scheduling, approve downtime, escalate maintenance, allocate operators |
| **Plant Manager** | Internal | Full backoffice + dashboards | MRP, maintenance, inventory, costing, executive MIS |
| **Customer** | Portal | `/my/home` | Track own orders, view progress, raise support tickets |

Full permission matrix: [`04-security-model.md`](04-security-model.md).

## 5. Success Criteria

| # | Criterion | Measured by |
|---|---|---|
| S1 | Zero manual Excel planning for daily schedules | Plans generated by the engine, not typed |
| S2 | Planned vs actual visible same-day, shift-wise | Daily Production Report available by shift close |
| S3 | 100% of downtime events carry a coded reason | Downtime Report has no "uncategorised" bucket |
| S4 | Machine utilisation % available per machine per day | Utilisation Report + OEE dashboard |
| S5 | Backlog and carry-forward computed automatically | Nightly snapshot cron, zero manual tracking |
| S6 | Preventive maintenance raised automatically before due date | Maintenance requests auto-created by cron |
| S7 | A new developer runs the whole stack in one command | `docker compose up -d` |
| S8 | ERP 10.8 can be integrated later without refactoring | Integration seam documented and stubbed |
